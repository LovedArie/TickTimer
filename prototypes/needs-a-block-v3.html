"Needs a block" — v3
PROTOTYPE
New in v3 — your four calls:
  • A late block no longer counts. Coverage is deadline-aware: a block must fall on or before the deadline, and must not already be in the past.
  • Re-arm is configurable — daily at a set time, or every N hours. Defaults to daily at 06:00.
  • "Not today" uses the same shape, defaulting to end of day.
  • The list now appears on the week view too — see note 3 for why that follows from the first change rather than being a separate decision.

1The coverage rule, precisely. A block covers a task only when 0 ≤ blockDay ≤ deadline, where deadline = max(dueDay, today). Two consequences worth naming. Overdue tasks stay satisfiable — the max(…, today) means a task due last week is covered by a block today, rather than being permanently un-fixable and nagging forever. And a block that already passed doesn't count — if Monday's block came and went and the task is still open, that time didn't do the job, so it needs new time. 4Re-arm and dismissal are the same mechanism. Both answer "when does this come back?", so both get the same control shape rather than two bespoke ones — a mode plus a parameter. In code that's one small ReturnPolicy value type with a nextReturn(from) function, used twice, instead of two similar-but-subtly-different implementations. Still open

Down to three.
  1. Should a dismissal survive a re-arm? Right now they're independent clocks: the review can re-arm at 06:00 while a task dismissed "until end of day" stays quiet. That seems right — dismissing is per-task, re-arming is per-review — but it does mean the gate can open onto a list shorter than the real backlog.
  2. Does "Find time" offer days other than today? Currently today only, on both views. But if a task is due Friday and today is full, the useful answer is Thursday. The week view makes that offer natural — it just isn't built here.
  3. A task dismissed every day for a week. Still unanswered. The app now knows the count; the question is whether it should say anything, and what wouldn't be obnoxious.
